# 안전성 확보조치 도구 구현·검증 기록

## 변경 범위와 기존 구조

기준 커밋: `28300dfdd7d69e77afdcde74b169afe61fc3b8ec`.

기존 서비스는 Next.js 16.2.6 / React 19.2.6 App Router다. `app/page.tsx`가 `components/privacy-risk/*` 화면을 선택하며 `useAssessment.ts`가 진행·답변·증적·초기화·내보내기를 관리한다. `lib/privacy-risk`에는 기존 26개 문항, 판정, 날짜, 저장, 보고서가 분리되어 있다. 기존 저장 키는 `privacy-risk-self-check-v1`이다. 결과 화면과 전용 인쇄 스타일, 사례 검색, 공개 의결서 연결, 독서 설정을 유지한다.

기존 파일의 수정은 `app/page.tsx`의 도구 선택기 import와 표시 2줄뿐이다. 기존 CSS·컴포넌트·26문항·109사례·72개 공개 의결서 문서·URL·앵커·데이터 저장키는 변경하지 않는다. 새 CSS는 CSS Module로 범위를 한정한다. 기존 `/`와 `/#about-risk`를 유지하고 `/safeguards`를 추가한다.

GitHub Actions `.github/workflows/ci.yml`의 기존 `npm test`가 새 테스트 파일도 실행한다. 배포 대상은 기존 `grasshopper-privacy-risk-check` 프로젝트 (`prj_waP3L3BPyq1E4sTFoESiJv18a6Bi`)와 기존 운영 도메인이다. 새 프로젝트나 DB·analytics를 생성하지 않는다.

## 기준 데이터

`data/safeguards/source.md`는 사용자가 지정한 조문별 대응표의 원문이다. `scripts/generate-safeguards.py`는 표 셀을 축약 없이 추출하여 다음 데이터를 생성한다.

|파일|내용|문항 수|
|---|---|---:|
|applicability.ts|F-01~F-15|15|
|general.ts|일반 안전조치|89|
|public-system.ts|공공시스템 추가 조치|24|
|encryption-risk.ts|R-01~R-26 / R-27~R-29|26 / 3|
|합계|핵심 조문 113개 포함|157|

질문·ID·조문·적용조건·증적·판단기준 원문 셀은 자동검사로 대조한다. 추가 입력 필드는 `fields.ts`, 원문에 따른 조건식은 `applicability-engine.ts`에 분리했다. 시스템·기관·정보항목이 함께 있는 혼합 환경의 세부 조합, 사건·예외 범위 등 사전정보만으로 확정할 수 없는 조건은 문항별 적용조건 확인을 요구한다. 불명확한 조건을 자동으로 해당 없음으로 바꾸지 않는다.

## 분기·판정

- M: 유형과 처리자 전체 정보주체 수로 계획 생략 예외를 판단한다. 교육·위탁·접속기록 의무를 함께 면제하지 않는다.
- G: 공공기관·대기업·중견기업 10만명 / 중소기업·단체 100만명 기준.
- I: 전년도 10~12월 저장·관리 이용자 일일평균 100만명 및 단말 권한·예외 범위.
- P/U: 지정 여부와 지정 공고·통보의 확인근거가 필요하며 운영기관 / 계정 직접 관리 이용기관을 분리한다. H-01을 U에 확대하지 않는다. G-05는 직접 계정관리 여부와 별개인 이용기관의 관련 사건 범위를 유지한다.
- R: 이번 암호화 판단 대상의 비이용자·주민등록번호 외 고유식별정보·내부망·위험도 분석 선택·영향평가 비대상을 함께 확인한다. 주민등록번호, 이용자, 인터넷망·DMZ는 제외한다. 적용대상 미확인일 때 R 모듈은 열리지 않으며 결과에도 미확인을 표시한다.
- 해당 없음에는 사유와 확인근거가 필요하다. 조건상 비적용은 별도 상태이며 원래 사용자 입력을 보존한다.
- 점검일과 사전조건 변경 시 이전 응답을 보존하고 재확인을 요구한다. 메모 수정만으로 재확인 완료 처리하지 않는다.
- 일반 / 공공 / R / 준비평가의 네 집계를 분리한다. 점수·법적 적합 확정 표현을 제공하지 않는다.
- M-13·14, A-01·07, N-03·04, L-01~07의 13개 개정 문항은 2026-11-01 전 준비평가다. 종전 의무는 면제되지 않으며 과거 법적 적합성 전체를 판정하지 않는다는 안내를 표시한다.

## 저장·결과·인쇄

신규 키는 `grasshopper-safeguards-check-v1`이다. 자동저장 실패를 표시하고 손상·버전 불일치 저장값을 임의 삭제하지 않는다. 새 도구 초기화는 해당 키 하나만 삭제한다. JSON에는 기준 버전·사전조건·원래 답변·평가 결과·비적용 상태·증적 참조를 함께 보존한다. 결과보고서는 4개 영역의 집계, 6개 조건의 판단근거, 조문별 세부결과, 미흡·추가확인 과제, 사전정보와 비공식 참고 안내를 포함한다.

기본정보 3개는 공란으로 진행할 수 있다. 실제 파일 업로드, 외부 전송, 비밀번호·토큰·키 수집 기능이 없다.

## 자동 검증

- `npm run lint`
- `npm run typecheck`
- `npm test`: 기존 26개 + 신규 25개 = 51개 검사
- `npm run test:data`: 기존 109사례·72의결서 문서·26문항 무결성
- `npm run build`: `/`, `/safeguards` 정적 Production 빌드
- `npm run test:render`: 두 경로·기존 앵커·도구 선택기·안내문

신규 검사에는 정확한 ID/문항 수/원문 셀, 미답변/추가확인, 비적용과 해당 없음, M 예외, 규모 및 망차단 경계, P/U/개발배포 역할, R 허용·금지·혼합 대상, L1/L2 상호배타, 2026-10-31/2026-11-01 시행시점, 조건 변경 재확인, 저장·초기화 격리가 포함된다.

위 자동 검증은 모두 통과했다(단위 검사 51개, 기존 데이터 무결성 8개, Production HTML 검사 2개).

## 브라우저 검증

Production 빌드를 Chromium에서 실행하여 13개 흐름을 확인했다. 기존 도구의 기본정보 공란 진행, 26개 문항, JSON 저장, 인쇄, 자동 복원, 109사례 화면과 초기화가 정상이다. 새 도구의 공란 진행, 증빙 없는 해당 없음의 추가확인 처리, 142개 세부행과 4개 집계의 JSON, 인쇄 보고서, 자동저장 후 재접속 복원, 날짜 변경 후 재확인, 초기화 시 기존 저장값 보존을 확인했다. 너비 390px 모바일 화면에서 가로 넘침이 없고 브라우저 실행 오류가 없다.
